## 1. ترتيب التشخيص

العطل يصلك على شكل عرض (Symptom)، وعملك أن تصل منه إلى إعداد واحد خاطئ

التجريب العشوائي يدفن السبب الأول تحت أسباب جديدة، فالترتيب ثابت:

1. **اقرأ ولا تخمن:** افتح `DaVinci Resolve > About DaVinci Resolve` واكتب النسخة ✔ (الدليل الرسمي ص 4337)، وإملاء القائمة الأولى على Windows ⚠ (فحص CHK-018)، وانسخ نص أي رسالة خطأ كما هو، واكتب الصفحة المفتوحة
2. **حدد الموضع:** أيظهر العرض في العارض فقط، أم في الملف الناتج، أم على الهاتف، أم في الكاميرا؟ لكل موضع شجرة فحص (الأقسام 3 إلى 7)
3. **اعزل:** غير متغيرا واحدا كل مرة، وانسخ التايم لاين قبل أي تعديل هدام فالنسخ أكثر أمانا من نقطة الاستعادة بحسب الدليل ✔ (الدليل الرسمي ص 88)
4. **قس قبل أن تغير:** مؤشر GPU وعداد FPS وTask Manager للأداء، والمقاييس (Scopes) للون: مخطط الموجة (Waveform) وباريد RGB (Parade) ومخطط المتجهات (Vectorscope)، وffprobe للملف
5. **أصلح الإعداد لا الصورة** (القاعدة أعلاه)
6. **أعد الفحص بالأداة نفسها وسجل:**

```text
FAULT LOG   date: ____   Resolve build: ____   driver: ____
symptom (one sentence): ____
where: viewer / rendered file / phone / camera
changed (one thing): ____
result: fixed / same / worse     CHK id: ____
```

احفظ السجل في `05_Docs\PROJECT_NOTES.txt` تحت عنوان FAULT LOG (انظر الفصل 2)، وهذا مثال معبأ:

```text
FAULT LOG   date: 2026-10-02   Resolve build: as shown in About   driver: as shown in NVIDIA app
symptom (one sentence): first reel looks washed on the phone only
where: phone
changed (one thing): Data levels = Auto
result: same     CHK id: CHK-089
```

## 3. الأداء والانهيارات

### 3.1 قس ثم اخفض

- كل عارض يعرض مؤشر حالة GPU وعداد FPS، والأخضر يعني أن في المعالجة سعة متاحة، والأحمر يعني أن القدرة لا تكفي لتشغيل ثابت بالزمن الحقيقي ✔ (الدليل الرسمي ص 194)
- افتح Task Manager بـ `Ctrl + Shift + Esc` لترى هل الحد هو GPU أم CPU أم القرص ◐
- ثم اختر من الجدول، واصعد درجة واحدة كل مرة وأعد القياس (السلم الكامل بالفصل 2 القسم 8)

| الحمل | ما تفعله | العلامة |
|---|---|---|
| فك RAW (R3D NE) | اخفض `Decode Quality` في `Project Settings > Camera Raw` للقص، فهو "the fastest solution"، و`Timeline Proxy Resolution` لا يفيد هنا | ✔ (الدليل الرسمي ص 196)، والدليل يقول إن لوحة Camera Raw معطلة تحت RCM ✔ (ص 229)، فإن ظهرت `Decode Quality` معطلة فانتقل إلى `Use GPU for R3D` ثم Proxy Media ⚠ (فحص CHK-030) |
| فك RAW على GPU | `Preferences > System > Decode Options > Use GPU for R3D` بأفضل خيار تجده في CHK-043 (انظر الفصل 2 القسم 7.3) | الاسم ✔ (الدليل الرسمي ص 99)، وأسرع خيار ⚠ (فحص CHK-043) |
| تلوين ومؤثرات | `Playback > Timeline Proxy Resolution` = `Half Resolution` (540 x 960 على تايم لاين 1080 x 1920) و`Render Cache` = `Smart` | ✔ (الدليل الرسمي ص 195 للتحجيم وص 200 للكاش) |
| H.265 من ZR (10-bit 4:2:0) | فعل `Decode H.264/HEVC using hardware acceleration` في `Preferences > System > Decode Options` (Studio) | الاسم ✔ (الدليل الرسمي ص 99)، والفائدة ⚠ (فحص CHK-044) |
| لا تكفي الخطوات | `Generate Proxy Media` أو `Generate Optimized Media`، وتلغى الوسائط المحسنة إن غيرت Camera Raw للمقطع | ✔ (الدليل الرسمي ص 198) |
| القرص | 6K R3D NE عند 25p نحو 195 MB/s: SATA SSD (نحو 500 MB/s) يكفي لمجرى واحد براحة ولمجريين بهامش ضئيل | حساب ✔، وسرعة القرص ◐ |

- تحت المسار أ (RCM) تتعطل لوحة Camera Raw في إعدادات المشروع وفي صفحة Color لأن RCM يتحكم بفك كل مقاطع RAW ✔ (الدليل الرسمي ص 229)، فإن ظهر `Decode Quality` معطلا فسجل ذلك ولا تغير المشروع، وانزل بالسلم: `Use GPU for R3D` ثم `Timeline Proxy Resolution` (لا يفيد إن كان الحمل فك RAW) ثم الوسائط الوسيطة أو المحسنة (انظر الفصل 2 والفصل 5) ⚠ (فحص CHK-030)
- H.265 من ZR بصيغة 4:2:0 فأي بطاقة RTX 40 مرشحة لفك العتاد، وProRes 422 HQ يفك على CPU، وR3D له مسار debayer على GPU ✔ (قائمة الترميزات) ◐ (جداول Puget)
- لتشخيص الإطارات المفقودة فعل `Stop playback when a dropped frame is detected` في `Preferences > User > UI Settings` ✔ (الدليل الرسمي ص 110)

> **خطأ شائع:** تسليم الريل بجودة القص المخفضة: Half decode لمقطع 6K يحتاج تكبيرا 1.129 عند الإطار العمودي الكامل، فهو للقص فقط (وتحت المسار أ لا يتاح Half أصلا، فاقرأ فحص CHK-030)، وفعل `Force debayer res to highest quality` في Deliver ✔ حساب

> **تحقق على جهازك (CHK-044، 25 دقيقة):**
> 1. شغل مقطع N-Log H.265، وافتح `Task Manager > Performance > GPU` واختر محرك `Video Decode`
> 2. سجل حمل `Video Decode` وحمل CPU والخانة مفعلة
> 3. أطفئ الخانة (`Save` وأعد التشغيل) وسجل القراءتين من جديد
> 4. ظهور الحمل مع التفعيل فقط يعني أن العتاد يعمل، وإلا فاستعمل وسائط وسيطة لـ H.265 ⚠ (فحص CHK-044، فـ Resolve بلا مؤشر مباشر)

> 📷 **[SHOT-17-01 | P1]** عارض Resolve بمؤشر حالة GPU وعداد FPS ظاهرين أثناء تشغيل مقطع H.265، بجانبه Task Manager على صفحة GPU ومحرك `Video Decode` مختار

> 📷 **[SHOT-17-02 | P2]** `Preferences > System > Decode Options` بخانة `Decode H.264/HEVC using hardware acceleration` وخيار `Use GPU for R3D` ظاهرين

### 3.2 إطارات خضراء أو متكتلة ◐

1. أطفئ `Decode H.264/HEVC using hardware acceleration` واحفظ، وأعد التشغيل عند الطلب ✔ (الدليل الرسمي ص 99 للخانة وص 96 لطلب إعادة التشغيل)
2. حدث إلى أحدث 21.1.x
3. شغل الملف في VLC وافحصه بـ ffprobe
4. حوله بـ `Generate Proxy Media` أو إلى ProRes أو DNxHR، وأعد نسخه من البطاقة بتحقق من البصمة (القسم 6.6)
- الدليل لا يضم قائمة بهذه الأعطال ✔

### 3.3 ذاكرة GPU

- متطلبات Blackmagic المعلنة لـ 21.1.1 ✔: بطاقة بذاكرة 4 GB على الأقل تدعم OpenCL 1.2 أو CUDA 12.8، وNVIDIA Studio Driver 581.57 أو أحدث، و16 GB VRAM للأدوات المتقدمة بالذكاء الصناعي، و32 GB RAM مع 12 GB VRAM للريندر في الخلفية
- ترتيب الإصلاح ◐: أغلق تطبيقات GPU الأخرى، ثم `Timeline Proxy Resolution`، ثم `Render Cache Color Output` للمقطع الثقيل (كليك يمين على المقطع في Edit أو Color) أو `Node Cache` للعقدة الثقيلة، ثم عطل أدوات الذكاء الصناعي (Magic Mask v2 وUltraNR وSpeed Warp، وكلها نسخة Studio فقط) أثناء القص
- اترك `GPU processing mode` و`GPU selection mode` على `Auto` (انظر الفصل 2)؛ الدليل يقول إن مستخدمي Nvidia على Windows يجب أن يستعملوا CUDA مع الدرايفر الصحيح ✔ (الدليل الرسمي ص 97)، ولا نفرضه قاعدة عامة
- اقرأ طراز البطاقة وذاكرتها من `Task Manager > Performance > GPU` (CHK-008)

### 3.4 انهيار أو تجمد

1. `Help > Create Diagnostics Log on Desktop` ✔ (الدليل الرسمي ص 4350): ينشئ سجلا للتشخيص، فأرفقه عند طلب المساعدة
2. الدرايفر: المتطلب "NVIDIA Studio driver 581.57 or newer" ✔، فابق على فرع Studio وثبت درايفرا معروفا طوال المشروع ◐ ممارسة
3. أطفئ فك العتاد (القسم 3.2) وعطل مؤثرات OFX وDCTL الخارجية واحدا واحدا، فـ 21.1 يعرض DCTL المفقودة فوق العارض ويتيح إعادة ربطها من LUT Manager ✔ (Read Me 21.1)
4. تأكد من المساحة على أقراص ذاكرة الريندر المؤقتة والوسائط الوسيطة والريندر، وResolve ينذرك بنافذة إن صار قرص هذه الذاكرة غير متاح ✔ (الدليل الرسمي ص 99)
5. لا تنزل إلى نسخة أقدم ✔ (القسم 1.1)

> 📷 **[SHOT-17-03 | P1]** قائمة `Help` مفتوحة وعنصر `Create Diagnostics Log on Desktop` ظاهر، وبجانبها نافذة `About DaVinci Resolve` تعرض النسخة

### 3.5 الاستعادة بعد عطل

- `Live Save` حفظ مستمر لا نقطة استعادة ◐، فأبق `Project Backups` و`Timeline Backups` مفعلين (انظر الفصل 2 القسم 9)
- تايم لاين تالف: كليك يمين على التايم لاين في Media Pool > `Restore Timeline Backup` واختر النسخة بتاريخها ✔ (الدليل الرسمي ص 88)
- مشروع تالف: Project Manager > كليك يمين على المشروع > `Project Backups` > اختر النسخة > `Load`، فتفتح كمشروع جديد ولا تستبدل الأصل إن كان مفتوحا ✔ (الدليل الرسمي ص 88)
- نقطة استعادة يدوية قبل التعديلات الكبرى: `File > Create Timeline Backup` (`Ctrl + Alt + S`، والدليل يطبع Option-Command-S) ✔ بالقاعدة
- احفظ نسخة `.drp` من المشروع عند كل مرحلة: Project Manager > كليك يمين على المشروع > `Export Project With Stills and LUTs` لأي مشروع ملون ✔ (الدليل الرسمي ص 76)، و`Export Project` أصغر ملف لكنه بلا لقطات Gallery وبلا LUT ✔ (انظر الفصل 1 القسم 1.4 والفصل 2 القسم 2)
- الدليل يذكر للنسخ الساعية واليومية رقمين متعارضين (8 و5، أو 2 و2) ✔ (الدليل الرسمي ص 87 وص 89)، فلا نقول "الافتراضي": اضبط أرقامك صراحة

> **تحقق على جهازك (CHK-024، 25 دقيقة):**
> 1. في `Preferences > User > Project Save and Load` اكتب أرقام `Project Backups` و`Timeline Backups` الفعلية، وأبق `Live Save` مفعلا، واضبط موقعا على قرص مادي مختلف وأرقاما صريحة
> 2. من Project Manager > `Project Libraries` > الأيقونة (i) اكتب مسار المكتبة (المتوقع قرب `C:\Users\<you>\AppData\Roaming\Blackmagic Design\DaVinci Resolve\Support\Resolve Disk Database\`)
> 3. أنشئ مشروعا تجريبيا، ثم `Back Up` لمكتبته، واحذف المشروع، واستعده
> 4. نفذ `File > Create Timeline Backup` مرة واحدة ⚠ (فحص CHK-024 للأرقام الافتراضية والمسار)

> 📷 **[SHOT-17-04 | P2]** `Preferences > User > Project Save and Load` بأرقام `Project Backups` و`Timeline Backups` وموقع النسخ ظاهرة

## 4. أعطال اللون

### 4.1 صورة باهتة

- منحنيات log مسطحة بتصميمها، وهذه قيم المنحنى لا قراءة مقياس: Log3G10 يضع الرمادي 18% عند 33.3% (الكود 341)، وN-Log عند 36.4% (الكود 372) وسواده مرفوع عند 12.4% (الكود 127) ✔ حساب

## 5. أعطال اللقطة

### 5.1 التشرط (Banding)

- السبب ◐: سلسلة التسليم 8-bit 4:2:0 وتدرج ناعم أكواده أقل مما تفرق العين، ويزيده منحنى حاد أو تنعيم ثم شحذ
- احكم من لقطة من الملف الناتج على الهاتف لا من العارض: مراقبة 10-bit "preferable" لتجنب تشرط ليس في البيانات، لكنها إعداد بطاقة الفيديو (Video bit depth) ✔ (الدليل الرسمي ص 143) وأنت بلا بطاقة، وسلسلة عارضك تختبرها بالصندوق أدناه
- حبيبات خفيفة بعد آخر تحجيم (انظر الفصل 11): في اختبار اصطناعي (تدرج 8-bit من نحو 41 درجة، x264 عند 5 و10 Mbps) خفضت خطأ الدرجات (RMS) بين 58% و84% ولم تلغه ◐، فالحبيبات "تلين التشرط" لا "تزيله"
- `Deband` (نسخة Studio فقط، فئة Resolve FX Revival) يعزل حواف التشرط ويخلط بكسلاتها، وأفضل نتيجة على منطقة معزولة بـ Qualifier أو نافذة وإلا لانت كل حواف الصورة ✔ (الدليل الرسمي ص 3639)
- لا مفتاح dither في Deliver ✔ (غياب من الدليل)، وماستر 10-bit لا يمنع تشرط 8-bit بعد إعادة ترميز Instagram ⚠ (فحص CHK-104)

> **تحقق على جهازك (CHK-051، 30 دقيقة، والتفصيل بالفصل 3 القسم 3.4):**
> 1. ضع مولد `Grey Scale` على تايم لاين 1080 x 1920، وكبر العارض إلى 100% بـ `Alt + Shift + Z` (الدليل يطبع Option-Shift-Z) ✔ (الدليل الرسمي ص 3076)، وفعل Cinema بـ `P` في صفحة Color ✔ (الدليل الرسمي ص 3049)، أو من `Workspace > Viewer Mode > Cinema Viewer` (الدليل يطبع Command-F، أي `Ctrl + F` على Windows) ✔ (الدليل الرسمي ص 23 وص 31)
> 2. عرض الدرجة بالبكسل = عرض المنحدر بالبكسل ÷ عدد الدرجات (256 لـ 8-bit و1024 لـ 10-bit)، فعلى منحدر بعرض 1080 بكسل تقع الدرجة نحو 4.2 بكسل لـ 8-bit ونحو 1 بكسل لـ 10-bit ✔ حساب، والحكم بمقارنة 8 bpc مقابل 10 bpc لا بالرقم المطلق
> 3. بدل `Output color depth` في NVIDIA بين 8 bpc و10 bpc، وبدل خانة إدارة ألوان Windows إن وجدت، وقارن المنحدر نفسه بعد كل تبديل
> 4. إن وجدت `Use 10-bit precision in viewers if available` فبدلها واحفظ وأعد التشغيل وقارن؛ الدليل يقول إنها تظهر على macOS فقط ✔ (الدليل الرسمي ص 106)، فإن لم تجدها فاكتب ذلك وأكمل
> 5. Lenovo تذكر 10-bit ولا تذكر هل هو أصلي أم 8-bit مع FRC ⚠ (فحص CHK-051)

### 5.2 الضجيج

- اعرض نحو اليمين عند الحساسية الأساسية ولا ترفع لقطة log ناقصة التعريض: يسجل ZR فيديو R3D NE عند ISO 800 أو 6400 بحسب `Base ISO sensitivity`، وما سواهما بيانات وصفية ✔ (Nikon)
- لوحة Motion Effects (Temporal NR وSpatial NR) "only available in the Studio version" ✔ (الدليل الرسمي ص 3513)، وفي Resolve FX أداة `Noise Reduction` (نسخة Studio فقط)
- عند الجمع بين NR والتلوين في عقدة واحدة تعالج NR أولا ✔ (الدليل الرسمي ص 3519)، ويسمح الدليل بوضعها أول الشجرة أو آخرها (الفصل 9 يضعها أولا في `NR` ◐)
- بخفة: NR القوية تمسح الجلد وتصنع هضابا تتشرط، وهي ثقيلة على VRAM ◐

### 5.3 الوميض

- كهرباء الإمارات 230 V و50 Hz (Wikipedia ◐)، فإضاءة التيار تومض بتردد 100 Hz ✔ حساب
- إجراء Nikon ✔: `Video recording menu > Video flicker reduction > Frequency` = `50 Hz`، وإن لم يكف فالوضع S أو M وغالق 1/100 أو 1/50 أو 1/25 s (1/48 ليس في قائمة Nikon)، والإضاءة الشديدة تضعف التقليل فاستعمل فتحة أصغر
- `Digital flicker reduction`: للصيغ الخام (R3D NE وN-RAW وProRes RAW HQ) الدليل الإلكتروني يقول معطلة وجداول Nikon تقول متاحة، فاعدها معطلة ⚠ (فحص CHK-117)، ولملفات H.265 وProRes 422 HQ بحجم 3840 x 2160 عند 25p يتيحها الدليل الإلكتروني بشروطه (الفصل 4 القسم 8) ⚠ (فحص CHK-117)
- نموذج حسابي لوميض جيبي عمقه 100% عند 100 Hz (الإضاءة الحقيقية تختلف) ✔ حساب: الغالق 1/50 و1/100 يبقي 0%، و1/48 يبقي 4.0%، و1/60 يبقي 16.5%، ولذلك مصور 30p بغالق 1/60 تحت 50 Hz يرى نبضا ◐، والمعتمد في الدليل 25p بغالق 1/50 (انظر الفصل 4)
- `Deflicker` (نسخة Studio فقط) يعالج فلورسنت يومض وحتى "rolling bars" على الشاشات ✔ (الدليل الرسمي ص 3640)، وله preset `Timelapse` و`Fluoro Light`، و`Color Stabilizer` (نسخة Studio فقط) يزيل تغيرات اللون والسطوع داخل اللقطة، واستعمله قبل التلوين ✔ (الدليل الرسمي ص 3545)

### 5.4 جيلو وانحراف

- لا أداة إصلاح rolling shutter في دليل Resolve ✔: إشارته الوحيدة في Fusion Camera Tracker، وحل التفافي بعقدة Optical Flow للتتبع لا للمونتاج ✔ (الدليل الرسمي ص 1875)

### 5.5 إطار أسود أو وامض أو تالف في الملف

- الأسباب ◐: ذاكرة الريندر المؤقتة (Render Cache) تالفة أو قديمة، أو `Use render cached images` مفعلة، أو فجوة عند قطع، أو مقطع Fusion أو Optical Flow فشل في إطار، أو نفاد ذاكرة GPU أثناء الريندر، أو حالة NVENC والدرايفر، أو إطار مصدر تالف
- الإصلاح بالترتيب:
  1. `Playback > Delete Render Cache > All` على المشروع المفتوح ✔ (الدليل الرسمي ص 206: افتح المشروع أولا ثم اختر الأمر)، أما زر `Clear Selected Cache` في `Playback > Manage Render Cache` فيحذف بلا تحذير وبلا تراجع ✔ (ص 206)
  2. في Deliver أطفئ `Use render cached images` و`Use proxy media` و`Use optimized media` ✔ (الدليل الرسمي ص 4121)
  3. أعد ريندر المدى الفاشل فقط بـ Mark In وMark Out
  4. جرب خيار `Encoder` غير NVIDIA (الخيار البرمجي) لهذا الريندر: الدليل يقول إن محطات NVIDIA بـ NVENC "will present alternative accelerated options" ✔ (الدليل الرسمي ص 4118)، ولا يسرد أسماء الخيارات، فاكتب الاسم الذي تراه ⚠ (فحص CHK-086)

- إطار واحد تالف: Resolve FX `Frame Replacer` (نسخة Studio فقط): `Replace This Frame` ثم `Replacement Method` = `From Previous` أو `From Next` أو `Blend Prev/Next` أو `Optical Flow` ✔ (الدليل الرسمي ص 3644)
- العثور على إطار وامض: لا كاشف آلي موثق، فانتقل بين نقاط القص بـ `Up Arrow` و`Down Arrow` ✔ (الدليل الرسمي ص 870)، وافتح Edit Index (عمودا `Record Duration` و`Source FPS`) ✔ (الدليل الرسمي ص 805 وص 806)، وهل يرتب النقر على عنوان العمود المقاطع؟ ⚠ (فحص CHK-071)
- للتدرب: أنشئ تايم لاين اختبار فيه مقطع من إطارين، وابحث عنه بالأسهم وبعمود `Record Duration`

### 6.3 معدل إطارات متغير وانجراف الصوت

- الدليل بلا نص عن VFR ✔ (غياب)، فسلوك Resolve معه ⚠ (فحص CHK-046)، والاحتياط رخيص: حول لقطات الهاتف إلى معدل ثابت قبل الاستيراد
- ما يوثقه الدليل للمقاطع المخالفة لمعدل المشروع: `Project Settings > Master Settings > Frame Interpolation > Retime Process` (Nearest وFrame Blend وOptical Flow) ✔ (الدليل الرسمي ص 145)، و`Mixed frame rate format` يتاح قبل استيراد الوسائط فقط ✔ (الدليل الرسمي ص 155)، ويثبت Resolve معدل التايم لاين عند دخول أول ملف إلى Media Pool ✔
- الكشف والتحويل ✔ (الأمران مختبران على Linux بـ ffmpeg وffprobe 6.1.1 وملف اصطناعي 30 fps، والقيمة `-r 25` لتطابق التايم لاين، وفي النسخ القديمة استبدل `-fps_mode cfr` بـ `-vsync cfr`):

```text
ffprobe -v error -select_streams v:0 -show_entries stream=r_frame_rate,avg_frame_rate,nb_frames,duration,color_transfer,color_primaries,pix_fmt:stream_side_data=rotation -of default=nw=1 clip.mov
ffmpeg -i in.mov -fps_mode cfr -r 25 -c:v libx264 -pix_fmt yuv420p -c:a copy cfr.mp4
```

- `r_frame_rate` المخالف لـ `avg_frame_rate` يعني معدلا متغيرا؛ ولا تكتب فوق الأصل أبدا
- `-r 25` على لقطة 30p يحذف إطارات فيغير الإيقاع، فهي نسخة لاختبار المزامنة؛ ولإبقاء المعدل الأصلي اكتب قيمة `avg_frame_rate` (مثلا `-r 30`)
- `color_transfer=arib-std-b67` يعني HLG (HDR): لا تحول المقطع بهذا الأمر (يخرج 8-bit SDR)، وصور بالهاتف بوضع SDR (انظر الفصل 6) ⚠ (فحص CHK-046)

- المزامنة: كليك يمين على المجلد > `Audio Sync > Auto Sync Audio` ثم `Synchronize Using` = `Timecode` أو `Waveform` ثم `Sync` ✔ (الدليل الرسمي ص 443 وص 444)
- افحص التزامن في بداية أطول لقطة ونهايتها، وأبق الصوت 48 kHz (انظر الفصل 15)
- صوت ZR: Linear PCM بتردد 48 kHz وعمق 24-bit أو 32-bit float (NEV وR3D وMOV) أو AAC (MP4) ✔، ومشغلات كثيرة لا تشغل ملفات float جيدا فاحكم من تايم لاين Resolve ✔

> 📷 **[SHOT-17-10 | P2]** نافذة cmd.exe بمخرجات ffprobe لـ `r_frame_rate` و`avg_frame_rate` لمقطع هاتف قبل التحويل وبعده

### 8.3 بطاقة الملف

- لا يغادر الملف جهازك قبل ثلاثة أمور ◐ سياسة الدليل: كتلة ffprobe، وقياس الصوت (نحو -14 LUFS مرجع عملي لا قاعدة Meta، والذروة الحقيقية (dBTP) -1.0 أو أقل)، ومشاهدة كاملة مرة واحدة
- الجدول المتوقع وأوامر القياس بالفصل 12 القسم 8
- قف وأصلح عند: وسم غير bt709 أو `unknown`، أو `color_range` غير `tv`، أو `r_frame_rate` مخالف لـ `avg_frame_rate`، أو ترميز غير H.264 High 8-bit 4:2:0 بأبعاد 1080 x 1920، أو صوت غير AAC بتردد 48000، أو ذروة فوق -1.0 dBTP، أو حجم فوق 300 MB (سقف توثيق Meta للنشر عبر API، حد احتياطي لا شرط للتطبيق)، أو edit list أو غياب FastStart إن مر الملف بأداة API ⚠ (فحص CHK-088)
- شغل الملف في مشغل ثان واسحبه بسرعة 2x

> **تحقق على جهازك (CHK-088، 30 دقيقة):**
> 1. فعل `Stop renders when a frame or clip cannot be processed` ثم صدر 20 إلى 30 ثانية بالـ preset (`Add to Render Queue` ثم زر الريندر في نسختك: `Start Render` تحت العارض، أو `Render All` تحت Render Queue، فحص CHK-086)
> 2. شغل أوامر ffprobe وebur128 وسكربت `atoms.py` (انظر الفصل 12 القسم 8) وقارن بالجدول المتوقع
> 3. صيغة `findstr` على Windows لم تجرب بعد ⚠ (فحص CHK-088)

## 10. العمل مع Claude عند العطل

- الجلسة بلا اتصال (أ): ترسل لقطات شاشة ونصوصا، ولا يرى Claude التايم لاين ولا يؤكد نتيجة ريندر من دون إطار أو مخرجات ffprobe منك، ويسأل عند الشك ولا يدعي أن بندا ⚠ صار مفحوصا (انظر الفصل 18) ✔
- الجلسة المتصلة بـ Resolve عبر MCP (ب): تقرأ حالة المشروع (الاسم وعدد التايم لاين ومعدل الإطارات والدقة والصفحة) وتبلغك قبل أي عمل، ولا تقرأ قيم الدرجة ولا تبني عقدا (انظر الفصل 16) ✔

| العطل | ما ترسله |
|---|---|
| لون الصورة | Waveform وParade بأربع نوافذ ومقياس Percentage، ولقطة Node Graph، ونافذة `Clip Attributes`، و`Project Settings > Color Management` |
| الأداء | لقطة العارض بمؤشر GPU وFPS، وTask Manager (GPU و`Video Decode`)، وصفحة `Decode Options` |
| الملف | نص مخرجات ffprobe (الفيديو والصوت والتنسيق) كما هو، ولقطة `Show Job Details` |
| Offline وانجراف الصوت | لقطة Media Pool بفلتر Offline، ونص ffprobe لمقطع الهاتف |
| دائما | النسخة من `About DaVinci Resolve`، والتاريخ، ورقم الفحص، وسطوع OSD إن كانت المشكلة لونية |

نحو 90 دقيقة على نسخة من مشروع `LAB_Day0_RCM` (انظر الفصل 19)، ولكل بند ثلاثة أسطر في `FAULT LOG`: ما فعلته، والمتوقع، وما قرأته:
1. **المستويات (فحص CHK-040):** على مقطعي غطاء العدسة والكرت الرمادي لـ N-Log (من تصوير المختبر، انظر الفصل 19) فعل `Bypass Color Management` وعطل كل العقد، ثم بدل `Data Levels` للمقطع بين `Video` ثم `Full` ثم `Auto`
   - المتوقع: جدول من ثلاثة إعدادات x (السواد والرمادي) على Waveform بمقياس `Percentage`، والمرجع لملف بمدى كامل نحو 12.4% (127) ونحو 36.4% (372) ⚠ (فحص CHK-040)
2. **التحويل المزدوج:** على مقطع N-Log موسوم في Media Pool بـ `Rec.2020` و`Nikon N-Log` أضف في آخر الشجرة عقدة CST (الدخل `Rec.2020` و`Nikon N-Log`، والخرج `DaVinci Wide Gamut` و`DaVinci Intermediate`، انظر الفصل 7)
   - المتوقع: تباين وتشبع زائدان؛ عطل العقد من اليسار على Parade حتى يزول الأثر، ثم احذف الـ CST
3. **Offline:** أغلق Resolve، وغير اسم مجلد الوسائط التجريبي في Windows Explorer، وافتح المشروع، ثم `Edit Index > Option > Filter Offline Clips`، وحدد المقاطع وأعد الربط بـ `Relink Selected Clips`
   - المتوقع: تعود المقاطع من Offline إلى الحالة العادية
4. **معدل ثابت (فحص CHK-046):** شغل أمر ffprobe على مقطع هاتف، وإن كان VFR فاصنع نسخة CFR بالأمر وقارن ffprobe قبلها وبعدها
   - المتوقع: يطابق `r_frame_rate` قيمة `avg_frame_rate` في النسخة
5. **الوسوم (فحص CHK-089):** صدر 5 ثوان بالوسمين `Same as Project` واقرأ ffprobe، ثم اضبط الوسمين صراحة وأعد
   - المتوقع: bt709 وbt709 وbt709 وtv، والوسم المفقود يظهر `unknown`
6. **QC والهاتفان (فحص CHK-099):** جهز مقطع المرجع بحسب CHK-099 (انظر الفصل 19) وليس ريلا عاديا، وعبئ له بطاقات QC الثلاث، وانشره نشرا خاصا، وقارن على الهاتفين
   - المتوقع: قائمة فروق لكل هاتف: مستوى الأسود والرمادي المتوسط والبشرة والتشرط
