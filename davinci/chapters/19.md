# 19. مختبر اليوم الأول: الفحوصات المرتبة

> **بطاقة الفصل**
> - الهدف: إغلاق كل بند ⚠ في الدليل بفحص على جهازك أنت: نصوص القوائم الفعلية، الافتراضيات، سلوك الشاشة، وسم الملف، ومعالجة Instagram
> - المتطلبات: Resolve Studio 21.x مثبت (انظر الفصل 1)، Windows 11، شاشة P32p-20، كاميرا ZR، آيفون وأندرويد
> - الوقت التقريبي: 126 فحصا في 11 جلسة، نحو 65.3 ساعة للكل، منها 28.6 ساعة لفحوصات CORE (61 فحصا): وزعها على أسبوعين بمعدل ساعتين يوميا
> - مخرجاتك: ورقة نتائج مكتملة، وملف `PROJECT_NOTES.txt`، وفرع غاما محسوم (G22 أو G24، ومعناهما في القسم 1.5)، وقيم DRT مقفلة في قالب مشروع محفوظ، وقالب تسليم (preset) محفوظ، وحزمة نتائج مرسلة لـ Claude

## 1. لماذا يوجد هذا المختبر

قرأنا في مراجعة المصادر النصوص الأولية (دليلا Resolve 21 و21.1 وملفات Readme ودليل Nikon للـ Log وRAW ووثائق Lenovo وورقة RED) فحسمنا أغلب التسميات والأرقام، لكن لا وثيقة تحسم ما يحدث على جهازك وأمام عينيك: نص القائمة الحقيقي، والافتراضي، وسلوك الشاشة، وما يكتبه Resolve في الملف، وما يفعله Instagram به

كل بند ⚠ في الدليل يغلقه فحص أو أكثر هنا، ومعرفات `CHK-001` إلى `CHK-126` ثابتة

الرمز D01 إلى D36 معرف قرار في سجل القرارات المرافق (DECISIONS.md): اكتبه في رسالتك لـ Claude ليعرف أي قرار تغيره نتيجتك

> **قاعدة:** كل ما تقرؤه في خانة "المتوقع" هو توقع من المصادر وليس حقيقة
>
> الموسوم ✔ موثق من نص رسمي (الدليل أو Readme أو Nikon) أو حساب قابل للتكرار، والموسوم ◐ قيم نماذج أو ممارسة أو مصدر واحد: سجل القيمة الحقيقية ولا تجبرها على التطابق، وما عدا ذلك ⚠ حتى تكتب نتيجتك
>
> لا يعرض الدليل بند ⚠ كقاعدة قبل أن تنفذ فحصه وتكتب نتيجته في ورقة النتائج، وبعد الفحص يرفع الدليل العلامة إلى ✔ مع التاريخ والبناء ("تم الفحص بتاريخ ... على Resolve 21.x.y")

> **تحقق على جهازك (CHK-001 إلى CHK-126):** إذا اختلف اسم الخيار قليلا عندك، ابحث عن نفس الوظيفة، وأرسل لقطة، واكتب الاسم الحقيقي: لا تخمن ولا تتخط الفحص

### 1.4 ما ترسله لـ Claude وبأي صيغة

- لقطة شاشة: اضغط `Win + Shift + S` واسحب على المنطقة والصقها في المحادثة
- للوحة في Resolve صور اللوحة كاملة بعنوانها، ولا تقص أبدا قائمة منسدلة مفتوحة
- النص: حدد النص بالماوس ثم اضغط Enter (أو `Ctrl + C` في Windows Terminal) ⚠ فحص CHK-002: اكتب الطريقة التي نجحت عندك، والصق النص كنص وليس كصورة للشاشة
- صورة الهاتف مقبولة لقوائم الكاميرا وصفحات OSD الشاشة، وللتوثيق فقط في لقطة المقارنة جنبا إلى جنب (SHOT-19-152 وSHOT-03-17)، ولا تقبل أبدا للحكم على اللون
- أضف دائما: بناء Resolve (`DaVinci Resolve > About DaVinci Resolve`) والتاريخ ومعرف الفحص وقيمة سطوع OSD إذا كان الفحص يخص الشاشة
- أسماء مقاطع المختبر: `LAB_<test>_<format>_<detail>` مثل `LAB_GREY_R3D_ISO800_EV0`
- أرقام (الدليل الرسمي ص N) هي صفحات PDF في دليل Resolve 21.1 ما لم يذكر النص دليل Resolve 21 باسمه

```text
CHK-029 | 2026-10-04 | Resolve 21.x.y.zz Studio | OSD __
النتيجة: أ / ب / أخرى
القيم: (ما قرأته بنصه الحرفي)
اللقطات: SHOT-19-41, SHOT-19-42
ملاحظات: (أي اختلاف في الاسم)
```

الرمز SHOT-19-NN مكان لقطة: P1 لا يحكم على الفحص بدونها وP2 مفيدة، ويضم هذا الفصل 20 حجز لقطة P1 داخل الفحوص (مذكورة في القسم 16)، وبقية اللقطات (33 من P1 و126 من P2) في جدول القسم 16

> **جلسة Claude:** إذا كانت جلستك متصلة بـ Resolve عبر MCP (انظر `CHK-025`) فهو يقرأ اسم المشروع والتايم لاين والمعدل والدقة والصفحة بنفسه، لكنه لا يرى شاشتك الفعلية ولا يقرأ قيم التلوين (D33)، فتبقى لقطاتك ونصوصك هي الدليل في كل ما يخص الشاشة والمقاييس
>
> وإذا كانت جلستك بلا اتصال فكل جواب يمر عبر لقطاتك ونصوصك، ولا يعلن Claude بندا ⚠ على أنه مفحوص قبل أن ترسل نتيجته (انظر الفصل 16 والفصل 18)

### 1.5 مفاتيح الرموز

| الرمز | معناه |
|---|---|

| المسار ب (عقد CST) | `DaVinci YRGB` غير مدار مع عقد تحويل مساحة اللون (CST)، وهو طريقة Nikon (D05) |

| DIM وLIT | حالة الغرفة المعتمة (DIM) وحالة الغرفة المضاءة (LIT) كما يصنفها `CHK-012` |
| DRT | محول العرض (Display Rendering Transform): `Input DRT` و`Output DRT` (D08) |
| OSD | قائمة الشاشة على الشاشة نفسها (On-Screen Display) |
| bpc | بت لكل قناة (bits per channel) |
| VFR وCFR | معدل إطارات متغير ومعدل إطارات ثابت |
| CORE وW1 وOPT | مستويات الفحوص (1.1) |
| ✔ و◐ و⚠ | علامات الثقة (القاعدة في بداية القسم 1) |
| مخطط الموجة (Waveform) | مقياس السطوع في Resolve، وتجده في المقاييس (Scopes) |

## 2. الجلسة 1: قبل فتح Resolve (المجموعة A)

نفذ هذه الجلسة قبل أول تشغيل لـ 21.x وقبل أول تصوير للمختبر

### CHK-001 نسخ احتياطي لكل شيء قبل أول تشغيل لـ 21.x (20 د)

- **الهدف:** حماية مشاريعك القديمة: المشروع الذي يفتح في 21.1 لا يفتح في 20.3.2، لكن مكتبة المشاريع نفسها تبقى مقروءة في 20.3.2 ✔ (Readme)
- **الاستثناء:** تخطه فقط إذا لم تكن لديك مشاريع قديمة

1. افتح Resolve القديم (المثبت الآن) واقرأ رقمه من `DaVinci Resolve > About DaVinci Resolve`
2. من Project Manager (الشاشة الرئيسية) اضغط يمين على كل مشروع واختر `Export Project...` واحفظ ملف `.drp` في `D:\Backups\drp\` (`D:` مثال: استعمل قرصا غير قرص النظام، ويثبت حرفه النهائي بعد `CHK-004`)
3. في الشريط الجانبي افتح `Project Libraries` واضغط (i) المحاط بدائرة بجانب المكتبة المحلية (Local) واختر `Back Up` واحفظ في `D:\Backups\library\`
4. اكتب رقم النسخة القديمة على ورقة
5. بعد ذلك فقط ثبت Resolve Studio 21.x

- **المتوقع:** أ) ملفات `.drp` ومجلد نسخة المكتبة موجودة وحجمها أكبر من 0؛ ب) لا مشاريع قديمة: اكتب "no legacy projects" وانتقل، وتجري اختبار الاستعادة لاحقا في `CHK-024`
- **أرسل:** لقطة Explorer للمجلدين (SHOT-19-01) ونص رقم النسخة القديمة
- **يحسم:** D03

### CHK-002 تثبيت ffprobe وffmpeg وMediaInfo وفحص Python (25 د)

- **الهدف:** أدوات تقرأ وسوم كل ملف تصدره أو تستورده وشدة صوته وتركيب MP4

1. افتح `cmd.exe` (وليس PowerShell: يعرض رسائل ffmpeg العادية كأنها أخطاء)
2. شغل `winget install Gyan.FFmpeg` ثم `winget install MediaArea.MediaInfo.GUI` (أسماء الحزم من الذاكرة ⚠ فحص CHK-002، وإذا فشل winget فنزل نسخ Windows من مواقع المطورين)
3. أغلق `cmd.exe` وافتحه من جديد وشغل `ffprobe -version` و`ffmpeg -version`
4. شغل `python --version`، وإذا لم يوجد Python فثبت Python 3 من python.org أو استعمل مفسر Resolve 21.1: `"C:\Program Files\Blackmagic Design\DaVinci Resolve\ResolvePython\ResolvePython.exe" --version` (المسار من Readme ◐: تأكد أنه موجود)
5. احفظ سكربتي مرفق 19-أ ومرفق 19-ب (آخر الفصل) في `D:\Projects\LAB\scripts\` الآن، وانقلهما إلى `05_Docs\scripts\` في `CHK-003`
6. أدوات النسخ (D23): على صفحات متطلبات المطورين تأكد أن Silverstack ليس له نسخة Windows وأن YoYotta لـ macOS فقط، ثم جرب OffShoot أو TeraCopy Pro بوجهتين على مجلد تجريبي (ادعاءات D23 تبقى ◐ حتى تقرأ الصفحات)

- **المتوقع:** ffprobe وffmpeg يطبعان رقم نسخة، وMediaInfo يفتح ملفا بعرض `Text`، ومفسر Python واحد يعمل
- **أرسل:** السطر الأول من `ffprobe -version` ومن نسخة Python نصا (SHOT-19-02)
- **يحسم:** D28 (روتين التحقق)، D23 (أدوات النسخ)

> **خطأ شائع:** تشغيل ffmpeg داخل PowerShell: يظهر الخرج العادي بلون الأخطاء فتظن أن الأمر فشل

### CHK-004 جرد الجهاز والمتعلم (10 د)

- **الهدف:** جمع الحقائق التي لم تستطع المصادر تحديدها: طراز GPU بالضبط، وVRAM، وRAM، ومكتبي أم محمول، والأقراص، وبناء Windows، وصيغ ZR ومعدل الإطارات الذي ستصور به فعلا، والهواتف

1. اضغط `Win + R` واكتب `winver` ثم Enter: سجل نسخة Windows 11 ورقم البناء
2. اضغط `Win + R` واكتب `msinfo32`: سجل System Model (مكتبي أم محمول) وProcessor وInstalled Physical Memory
3. افتح Task Manager > Performance: سجل نوع كل قرص وحجمه، واسم GPU و`Dedicated GPU memory`
4. اكتب: طراز الهاتفين ونسخة Instagram على كل منهما، وطريقة توصيل الشاشة الآن (DP أم HDMI أم USB-C)، والبطاقات التي تملكها (CFexpress Type B: الحجم وفئة السرعة، وmicroSD)، وحروف الأقراص المخططة في D32

- **المتوقع:** قائمة من 12 إلى 15 جوابا قصيرا
- **أرسل:** الأجوبة نصا ولقطة Task Manager > Performance للـ GPU (SHOT-19-04)
- **يحسم:** D02، D03 (بيان 16 GB VRAM)، D23 (خطة الأقراص)، D26 (فك الترميز بالعتاد على هذه البطاقة)

> 📷 **[SHOT-19-04 | P1]** Task Manager تبويب Performance قسم GPU: يظهر اسم البطاقة و`Dedicated GPU memory`

### CHK-006 إصدار فيرموير ZR وجرد قوائم الكاميرا (35 د)

- **الهدف:** معرفة الإصدار وأسماء قوائم الكاميرا بالضبط قبل التصوير (الدليل يذكر أرقام البنود والكاميرا يجب أن توافقها)

1. في Setup menu افتح `Firmware version` واكتب الرقم، المعروف: 1.00 (2025-10-24 ◐) و1.10 (2026-01-27 ✔) و1.11 (2026-03-17 ◐)، أما 2.00 فأعلنت Nikon عنه في 2026-09-08 وقالت إنه مجدول للصدور في 2026، ولم يتأكد صدوره ✔ (للإعلان)
2. في Video recording menu افتح `Video file type` واكتب القائمة (المتوقع: R3D NE 12-bit وN-RAW 12-bit وProRes RAW HQ 12-bit وProRes 422 HQ 10-bit وH.265 10-bit و8-bit وH.264 8-bit)
3. لكل نوع افتح `Tone mode` واكتب الخيارات (المتوقع: R3D NE ثابت على Log3G10؛ وN-RAW وProRes RAW HQ وProRes 422 HQ: SDR أو N-Log؛ وH.265 10-bit: SDR وHLG وN-Log)
4. مع R3D NE افتح `ISO sensitivity settings`: `Base ISO sensitivity` منخفض (800) وعال (6400) ونطاقات ISO
5. في Custom Settings g Video اكتب أسماء وأرقام: `Extended shutter speeds (S/M)` (g12) و`Shutter mode` (g13) و`View assist` (g14) و`3D LUT` (g15) و`Zebra pattern` (g16) و`Brightness information display` (g19) و`Custom monitor shooting display` (g21)

## 3. الجلسة 2: Windows وNVIDIA والشاشة (المجموعة B)

الهدف: لا شيء بين Resolve واللوحة يغير الصورة

### CHK-008 طراز الرسوميات وVRAM وسائق Studio (10 د)

- **الهدف:** معرفة طراز RTX 40 بالضبط والتأكد أن السائق من فرع Studio وبرقم 581.57 أو أحدث ✔ (Readme)

1. في `cmd.exe` شغل `nvidia-smi` وانسخ النص كله
2. افتح Task Manager > Performance > GPU وسجل `Dedicated GPU memory`
3. افتح تطبيق NVIDIA (أو NVIDIA Control Panel > Help > System Information) واقرأ هل السائق Studio Driver
4. إذا كان Game Ready فثبت Studio Driver من موقع NVIDIA واكتب رقمه، ولا تحدثه في منتصف مشروع

- **المتوقع:** أ) اسم RTX 40 (جيل Ada: فيه NVENC وNVDEC وبلا فك 4:2:2 بالعتاد) وسائق 581.57 أو أحدث من فرع Studio؛ ب) RTX 50: تتغير ملاحظة فك 4:2:2 في D26؛ ج) VRAM أقل من 16 GB: قد تحذر أدوات الذكاء الاصطناعي (انظر `CHK-085`)
- **أرسل:** نص `nvidia-smi` ولقطة (SHOT-19-08)
- **يحسم:** D03، D26

> 📷 **[SHOT-19-08 | P1]** نافذة تطبيق NVIDIA أو NVIDIA Control Panel > Help > System Information: يظهر رقم السائق ونوعه (Studio Driver)

### CHK-009 إعدادات عرض Windows 11 (10 د)

1. افتح Settings > System > Display واختر الشاشة P32p-20
2. افتح `HDR` (مفتاح "Use HDR") وأطفئه، وأطفئ `Auto HDR` (Settings > System > Display > HDR)
3. أطفئ `Night light`
4. إذا وجدت مفتاحا اسمه `Automatically manage color for apps` فأطفئه (الاسم من وصف خارجي ⚠ فحص CHK-009، ويظهر في بعض بناءات Windows 11 22H2 فما فوق فقط)

6. أغلق أي أداة من نوع f.lux أو "حماية العين" من أي شركة

- **أرسل:** لقطة صفحة Display (SHOT-19-09) وصفحة HDR (SHOT-19-10) وتبويب Devices في Color Management (SHOT-19-11)

### CHK-010 وصلة DisplayPort وصيغة إشارة NVIDIA (15 د)

1. وصل كابل DisplayPort قصيرا معتمدا من خرج DP في كرت الشاشة إلى مدخل DP في الشاشة (ليس HDMI ولا USB-C)
2. في OSD الشاشة اضبط `Port Settings > Input Signal` = `DP` (أو `Auto`) و`Port Settings > DP Select` = `DP 1.2` (الافتراضي)
3. اضغط يمين على سطح المكتب > `NVIDIA Control Panel` > `Display > Change resolution` واختر 3840 x 2160 و60 Hz
4. اختر `Use NVIDIA color settings` واضبط `Output color format` = RGB و`Output color depth` = 10 bpc و`Output dynamic range` = Full، واكتب الخيارات التي تعرضها القوائم
5. في `Display > Adjust desktop color settings` اكتب القيم (المتوقع افتراضية: Brightness 50 وContrast 50 وGamma 1.00 وDigital vibrance 50 وHue 0) وأعدها للافتراضي إن اختلفت

- **المتوقع:** أ) 10 bpc معروض ومطبق: جيد؛ ب) 10 bpc غائب أو 8 bpc فقط: الوصلة هي الحد، HDMI 2.0 يحمل 4K60 بـ 8 bpc RGB فقط (14.256 من 14.4 Gbit/s) أو 10-bit كـ 4:2:2 فقط ✔ (حساب)، وUSB-C قد ينزل إلى مسارين DP أي 4K30 بـ 8 bpc ✔ (حساب) والسلوك ⚠ (فحص CHK-010): أصلح التوصيل أولا؛ ج) قد يعرض Windows 10 bpc بينما يركب سطح المكتب بـ 8-bit: `CHK-051` يحسم
- **أرسل:** لقطة صفحة NVIDIA والقوائم مفتوحة (SHOT-19-12) ولقطة Adjust desktop color settings (SHOT-19-13)
- **يحسم:** D14

> 📷 **[SHOT-19-12 | P1]** صفحة NVIDIA Control Panel > Display > Change resolution مع قائمة `Output color depth` مفتوحة

### CHK-011 جرد قائمة OSD في P32p-20 والإعدادات الآمنة (20 د)

- **الهدف:** استبدال ما تتذكره عن الشاشة بما تعرضه وحدتك، لأن دليل Lenovo لا يذكر بند gamma ولا حرارة اللون ولا معايرة

1. افتح OSD واكتب شجرة القوائم: `Monitor Controls` (Brightness وContrast) و`Advanced Settings` (Dynamic Contrast وOver Drive وColor Mode وAspect Ratio وButton Repeat Rate) و`Port Settings` (Input Signal وUSB Charging وDP Select وUSB Source Selections) و`Menu Settings`
2. اكتب قائمة `Color Mode` (حسب دليل Lenovo: sRGB وBT.709 وDCI-P3 وNeutral وReddish وBluish وLow Blue Light وCustom) وأيها المختار الآن (الدليل يذكر "Reddish" كافتراضي وقد يكون خطأ توثيق)
3. اضبط `Dynamic Contrast` Off و`Over Drive` Normal و`DP Select` DP 1.2 و`Input Signal` DP، ولا تختر Color Mode الآن
4. اكتب قيمتي Brightness وContrast (المصنع 75 و75)
5. ابحث عن أي بند اسمه gamma أو colour temperature أو K أو calibration، بما في ذلك داخل `Custom`
6. صور كل صفحة OSD، وملاحظة: الضغط على زر Menu عشر ثوان يقفل القائمة أو يفتحها

- **المتوقع:** أ) لا بند gamma (دليل المستخدم يقول لا يوجد) و`Custom` فيه Red وGreen وBlue من 0 إلى 100 فقط ✔؛ ب) يوجد بند gamma أو حرارة لون في وحدتك: أرسله، فيكسب D10 طريقا أفضل (ضبط الشاشة على 2.2 أو 2.4 مباشرة)؛ ولا يحسم هذا الفحص هل اللوحة 10-bit أصلية أم 8-bit مع FRC (انظر `CHK-051`)
- **أرسل:** صور هاتف لكل صفحة OSD (SHOT-19-14 وSHOT-19-15 وSHOT-19-16)
- **يحسم:** D10، D11، D14

> 📷 **[SHOT-19-14 | P1]** صفحة `Advanced Settings` في OSD الشاشة وفيها قائمة `Color Mode` (صورة هاتف مسموحة)

### CHK-012 تسخين الشاشة وتصنيف حالة الغرفة (DIM أو LIT) (15 د)

- **الهدف:** قاعدة موضوعية لسؤال "هل أستطيع الحكم على الظلال والتباين الآن؟"، وهذه بوابة D10 وD11، وإضاءة غرفتك متغيرة فسجل كل تهيئة

1. سخن الشاشة 30 دقيقة على سطوع OSD الذي تستعمله عادة
2. اجعل الشاشة كلها سوداء: Settings > Personalization > Background > `Solid color` أسود، واضغط يمين على سطح المكتب > `View` وأزل علامة `Show desktop icons`، واضغط `Win + D`
3. اجلس في موضع التلوين (60 إلى 90 سم من الشاشة)
4. لكل تهيئة إضاءة تستعملها (سقف مضاء، سقف مطفأ، مصباح مكتب، ستائر مفتوحة أو مغلقة، نهار أو ليل) انظر إلى الشاشة السوداء: إذا رأيت انعكاسات جدران أو مصابيح أو نوافذ أو وجهك فالحالة المضاءة **LIT**، وإن لم تر شيئا فالحالة المعتمة **DIM**
5. أضف إضاءة خلفية محايدة خلف الشاشة إن أمكن (شريط LED أبيض من نوع D65؛ هدف "نحو 10% من أبيض الشاشة" ذاكرة معايير ⚠ فحص CHK-012)
6. لاحقا في Resolve أعد الاختبار بمولد `10 Step` (انظر `CHK-038`): في DIM تتميز الخطوتان الأولى والثانية عن الأسود، وفي LIT تندمجان ◐ (قاعدة تقريبية)

- **المتوقع:** أ) تهيئة واحدة على الأقل تعطي DIM بشكل متكرر؛ ب) لا تهيئة تعطيها: فرع الغاما G22 (D10) وتؤجل موافقات الظلال والبشرة إلى اختبار الهاتف
- **أرسل:** جدول صغير "التهيئة > DIM أو LIT" نصا، وصورة هاتف للغرفة وليس للشاشة (SHOT-19-17)
- **يحسم:** D10، D11 (بوابة الغرفة)

### CHK-013 تقدير الغاما بلا جهاز قياس (مخطط الخطوط) (30 د)

قبل البدء نفذ `CHK-014` وثبت سطوع OSD المؤقت، فكل مقارنة بين الأوضاع بهذا السطوع نفسه

- **الهدف:** معرفة أي `Color Mode` في OSD أقرب إلى غاما 2.2 أو 2.4 قبل وصول جهاز القياس، لأن OSD لا يعرض الغاما ولا يغيرها
- **الأصل:** الطريقة ممارسة معيارية في العرض، اشتقها كاتب الدليل ولا نص من المصادر يوثقها ◐، ودقتها نحو ±0.2 غاما
- **المبدأ:** خطوط سوداء وبيضاء بعرض بكسل واحد تعطي 50% من الضوء بالضبط، ومربع رمادي ثابت بكود `255 x 0.5^(1/gamma)` يشبه الخطوط فقط إذا طابقت غاما الشاشة تلك الغاما
- الأكواد (8-bit) ✔ (حساب): غاما 2.0 = 180، و2.1 = 183، و2.2 = 186، و2.3 = 189، و2.4 = 191، و2.5 = 193، و2.6 = 195، وsRGB piecewise = 188

1. شغل سكربت مرفق 19-أ (`python make_gamma_chart.py`): يكتب `gamma_chart.png` (3840 x 2160، رمادي 8-bit)
2. اضبط مؤقتا Settings > System > Display > `Scale` على 100% (وإلا يعيد Windows تحجيم الصورة وتضبب الخطوط)
3. افتح الصورة في Microsoft Edge واضغط `Ctrl + 0` (100%) ثم `F11` (ملء الشاشة)
4. اجلس على بعد 1 إلى 2 م حتى تمتزج الخطوط في رمادي مسطح
5. المربعات الثمانية من اليسار إلى اليمين: غاما 2.0 و2.1 و2.2 و2.3 و2.4 و2.5 و2.6 وsRGB، وابحث عن المربع الذي يكاد يختفي في الخطوط
6. كرر لكل `Color Mode` قد تستعمله (`sRGB` و`BT.709`، و`Custom` فقط إن غيرته) بسطوع OSD نفسه
7. كرر في يوم ثان
8. أعد مقياس Windows

- **المتوقع:** رقم مربع لكل وضع، أ) وضع `BT.709` يطابق مربعا قرب 2.4 وsRGB يطابق 2.2 أو sRGB (فرضية ⚠ فحص CHK-013: لا غاما موثقة لأوضاع P32p-20): G24 ممكن إذا أمكن جعل الغرفة DIM؛ ب) كل الأوضاع تطابق نحو 2.2: G22؛ ج) تختلف النتائج بين الأيام أو لا تفرق بين 2.2 و2.4: عاملها G22 وأعد القرار بعد `CHK-015`، والمربعان 2.2 وsRGB لا يتميزان بالعين
- **أرسل:** لكل Color Mode: المربع المطابق (قيمة الغاما) واسم الوضع وسطوع OSD نصا (SHOT-19-18)
- **يحسم:** D10، D11

> **خطأ شائع:** تصوير المخطط بالهاتف والحكم من الصورة: لا تفيد هنا أبدا، فالحكم بعينك على الشاشة نفسها

### CHK-014 سطوع مؤقت بلا جهاز قياس (5 د)

- **الهدف:** سطوع مؤقت ثابت، لأن سطوع الأبيض لا يضبط بلا جهاز قياس وموضع منزلق OSD لنحو 100 cd/m2 مجهول

3. اكتب قيمة OSD والتاريخ في `PROJECT_NOTES.txt` باسم "unmeasured"

- **يحسم:** D11 (المرحلة المؤقتة)

### CHK-122 أي نصوص ألوان للمشروع والمقطع يقبلها السكربت على 21.x (OPT، 50 د)

**أ) نصوص الألوان**

1. في مشروع تجريبي استعمل مفتاحا واحدا في كل نداء، واقرأ كل مفتاح بعده
2. اضبط في الواجهة وقارن `dict(proj.GetSettings())` قبل التغيير وبعد تغيير شيء واحد لـ `DaVinci WG/Intermediate` و`REDWideGamutRGB/Log3G10` و`Rec.709 Gamma 2.4` و`Rec.709 Gamma 2.2` و`Rec.709 (Scene)` و`Rec.709-A` و`Nikon N-Log`
3. اضبطها بالسكربت واقرأها، وكرر الاختبار تحت DaVinci YRGB

**ب) تصفير DRT**

4. اقرأ `inputDRT` و`outputDRT` و`useInverseDRT` و`rcmPresetMode`، وكرر بكتابة كتلة DRT قبل التغيير وبعده

**ج) وسوم المقاطع**

**د) مواءمة 9:16**

7. ضع مقطع 4K بنسبة 16:9 في تايم لاين عمودي، وقارن قيم عدم التطابق في الـ API بالواجهة، وجرب `SmartReframe()`

- **المتوقع:** قائمة بالنصوص المقبولة، وسكربت `rs_project.py` بوضع `APPLY` للمسار أ (الفصل 16) لا يستعمل غيرها
- **أرسل:** الجداول (SHOT-19-175)
- **يحسم:** D33

### CHK-125 باقي مجهولات السكربت في مختبر واحد (OPT، 70 د)

1. `Graph.SetLUT`: جرب LUT في مجلد LUT الخاص بك (اسما مجردا ومسارا مطلقا) وفي المجلد الرئيسي وفي مجلد فرعي منه وفي مجلد أضفته في `Preferences > System > General > LUT Locations`، ثم `RefreshLUTList()`
2. `AddVersion`: هل ينشئ نسخة فارغة أم منسوخة؟ قارن `GetVersionNameList(0)` و`GetNumNodes()` قبل وبعد
3. `ApplyGradeFromDRX` على رسم Group Pre-Clip وعلى رسم Timeline، و`ImportStills` مع `.drx`؛ ومع نقاط بطبقتين: هل يطبق Resolve 21.x كل الطبقات؟
4. في Fusion Preferences > Path Maps اكتب المسارات الحقيقية لـ `UserData:` و`AllData:` و`Scripts:` و`Fuses:` و`Edit templates:` و`Macros:`
5. DCTL: شغل `resolve.ValidateDCTL(open(path).read())` على ملف سليم وآخر معطوب (الفصل 16، القسم 9)، وطبق DCTL من قائمة LUT في قائمة العقدة اليمنى، ثم `Reload DCTL`، وأعد التشغيل لترى ملفا جديدا
6. في `run_script` الأصلي المحمي: هل يجد `globals().get("resolve")` الكائن؟ وأي وحدات مسموحة؟
7. العربية: اضبط `transcriptionLanguage` وجرب `Timeline.CreateSubtitlesFromAudio` بعد تثبيت حزمة اللغة
8. (اختياري) Lua: اكتب كيف يحصل `fuscript.exe` على `resolve`

- **المتوقع:** جدول إجابات
- **أرسل:** الجدول نصا (SHOT-19-178)

### مرفق 19-أ: make_gamma_chart.py (لـ CHK-013)

يكتب `gamma_chart.png` (3840 x 2160، رمادي 8-bit) بمكتبة Python القياسية فقط، المربعات من اليسار إلى اليمين: غاما 2.0 و2.1 و2.2 و2.3 و2.4 و2.5 و2.6 وsRGB، وقد جربناه وفحصنا الصورة في 2026-10-02 (أكواد المربعات 180 و183 و186 و189 و191 و193 و195 و188)

```python
"""make_gamma_chart.py: writes gamma_chart.png (3840x2160, 8-bit grey) with the Python standard library only"""
import zlib, struct
W, H = 3840, 2160
gammas = [2.0, 2.1, 2.2, 2.3, 2.4, 2.5, 2.6]          # boxes left to right
def code(g): return round(255 * 0.5 ** (1 / g))         # solid grey that equals 50% light
vals = [code(g) for g in gammas]
srgb = round(255 * (1.055 * 0.5 ** (1 / 2.4) - 0.055))  # box 8 = sRGB piecewise
vals.append(srgb)
n = len(vals); bw, bh = 380, 700; gap = (W - n * bw) // (n + 1); top = (H - bh) // 2
boxes = [(gap + i * (bw + gap), gap + i * (bw + gap) + bw) for i in range(n)]
rows = []
for y in range(H):
    base = 0 if y % 2 == 0 else 255                     # 1-pixel black/white lines
    row = bytearray([base]) * W
    if top <= y < top + bh:
        for (x0, x1), v in zip(boxes, vals):
            row[x0:x1] = bytes([v]) * (x1 - x0)
    rows.append(b"\x00" + bytes(row))
raw = b"".join(rows)
def chunk(t, d): return struct.pack(">I", len(d)) + t + d + struct.pack(">I", zlib.crc32(t + d) & 0xffffffff)
png = b"\x89PNG\r\n\x1a\n" + chunk(b"IHDR", struct.pack(">IIBBBBB", W, H, 8, 0, 0, 0, 0)) + chunk(b"IDAT", zlib.compress(raw, 6)) + chunk(b"IEND", b"")
open("gamma_chart.png", "wb").write(png)
print("boxes (gamma -> 8-bit code):", dict(zip([str(g) for g in gammas] + ["sRGB"], vals)))
```

يفحص FastStart وedit list في MP4 بلا MediaInfo: شغل `python atoms.py Reel.mp4`، وقد جربناه على ملف اختبار في 2026-10-02 (طبع `FASTSTART` و`edit list present: True - count 2` لملف صنعه ffmpeg بإطارات B وصوت AAC)

```python
import struct, sys
CONT = {b'moov', b'trak', b'edts', b'mdia', b'minf', b'stbl'}

def walk(f, pos, end, depth, out):
    while pos < end:
        f.seek(pos); head = f.read(8)
        if len(head) < 8: break
        sz, typ = struct.unpack('>I4s', head); hdr = 8
        if sz == 1: sz = struct.unpack('>Q', f.read(8))[0]; hdr = 16
        elif sz == 0: sz = end - pos
        if sz < hdr: break
        out.append((depth, typ.decode('latin1'), pos, sz))
        if typ in CONT: walk(f, pos + hdr, pos + sz, depth + 1, out)
        pos += sz

out = []
with open(sys.argv[1], 'rb') as f:
    f.seek(0, 2); size = f.tell(); walk(f, 0, size, 0, out)
top = [t for d, t, p, s in out if d == 0]
print('top-level:', top)
print('FASTSTART (moov before mdat)' if top.index('moov') < top.index('mdat') else 'NOT faststart (moov after mdat)')
el = [t for d, t, p, s in out if t == 'elst']
print('edit list (elst) present:', bool(el), '- count', len(el))
```
