# 02. تجهيز Windows وRTX 40 والأداء وإدارة الوسائط

> **بطاقة الفصل**
> - الهدف: جهاز Windows 11 جاهز لـ Resolve Studio 21.x: درايفر صحيح، Windows لا يغير الصورة، Preferences مضبوطة، تخزين مرتب، سلم أداء مجرب بالأرقام، ونسخ احتياطي جربت استعادته
> - المتطلبات: Resolve Studio 21.x (النسخ وسياسة الترقية: انظر الفصل 1)، وصلاحية مدير على Windows، والشاشة P32p-20 موصولة (ضبطها: انظر الفصل 3)
> - الوقت التقريبي: نحو 3.5 ساعات (210 دقائق) للفحوصات الأساسية CORE التي تنفذها هنا (CHK-001 وCHK-003 وCHK-004 وCHK-008 وCHK-009 وCHK-020 إلى CHK-024 وCHK-030 وCHK-031 وCHK-043)، وهي تسبق أول ريل وتنجز خلال أسبوعين، و135 دقيقة للفحوصات المؤجلة W1 (CHK-019 وCHK-026 وCHK-044 وCHK-045 وCHK-118) بين الأسبوع 1 والأسبوع 4، أما الفحوصات الأخرى المذكورة بالإحالة فجدولها في الفصل 19
> - مخرجاتك: نسخ احتياطية للمشاريع القديمة (ملفات drp ونسخة للمكتبة)، سطر بموديل البطاقة والدرايفر، Preferences مضبوطة، هيكل مجلدات على الأقراص، جدول نتائج لفك الترميز وسلم الأداء، ومكتبة مشاريع جربت نسخها واستعادتها
> - العلامات: ✔ موثق، ◐ مصدر واحد أو توصية معقولة، ⚠ غير مؤكد وعليك فحصه (برقم الفحص)
> - أرقام الصفحات (ص) هي صفحات PDF في دليل Resolve 21.1 الرسمي، إلا إذا ذكرنا غير ذلك

## 2. قبل أول تشغيل لـ 21.x: النسخ الاحتياطي واختبار الاستعادة

الترقية باتجاه واحد ✔: لا يفتح 20.3.2 المشاريع التي أنشأتها أو فتحتها في 21.1، أما مكتبة المشاريع نفسها فتبقى مقروءة هناك (Readme الرسمي لـ 21.1.1)

وتوصي Blackmagic في الـ Readme بنسخة كاملة للمكتبة ونسخ فردية للمشاريع قبل فتحها بـ 21.1.1 ✔

الخطوات (فحص CHK-001، 20 دقيقة، وتتخطى الخطوات 1 إلى 3 إن لم تكن عندك مشاريع قديمة):
1. افتح النسخة القديمة واقرأ رقمها من `DaVinci Resolve > About DaVinci Resolve` واكتبه
2. في Project Manager اضغط كليك يمين على المشروع واختر `Export Project With Stills and LUTs` للمشاريع الملونة (فيها لقطات Gallery وجدول ألوان (LUT)) و`Export Project` للمشروع الخالي منها فقط، واحفظ ملف `.drp` في `F:\Backups\drp\`، ولعدة مشاريع حددها معا واختر `Export Projects` (الدليل الرسمي ص 76)
3. في شريط Project Manager الجانبي افتح `Project Libraries` واضغط حرف (i) داخل الدائرة بجانب المكتبة المحلية (Local)، ثم `Back Up` واحفظ في `F:\Backups\library\` (الدليل الرسمي ص 83)
4. ثبت Resolve Studio 21.x بعد ذلك فقط
5. اختبر الاستعادة على مكتبة تجريبية قبل أن تفتح أي مشروع قديم في 21.x (القسم 9.3، فحص CHK-024)، فالمكتبة التجريبية لا تمس مشاريعك الحقيقية

ملف `.drp` لا يحتوي الوسائط ✔

أسماء المسارات وأحرف الأقراص أمثلة، فاستعمل قرصا غير قرص النظام (جدول الأقراص بالقسم 6.2)

> 📷 **[SHOT-02-01 | P1]** صفحة Project Manager في Resolve والشريط الجانبي Project Libraries ظاهر، ونافذة تفاصيل المكتبة (الدائرة i) مفتوحة وزر Back Up ظاهر، بحيث يظهر مسار المكتبة وحالتها

> **تحقق على جهازك (CHK-001):** أرسل لقطة لمجلدي النسخ الاحتياطي في Explorer (حجم الملفات أكبر من صفر، وهي اللقطة SHOT-19-01 بالفصل 19) ورقم النسخة القديمة نصا
>
> إذا اختلف اسم القائمة عندك أو لم تجد `About DaVinci Resolve` تحت `DaVinci Resolve`، ابحث عن نفس الوظيفة واكتب المسار الحقيقي (فحص CHK-018)

## 3. جرد الجهاز والدرايفر

### 3.1 اقرأ جهازك ولا تخمنه

لا نعرف موديل بطاقتك ولا ذاكرتها (VRAM) ولا الـ RAM ولا هل جهازك مكتبي أو لابتوب، فلا تبن قرارا على تخمين ⚠ (فحص CHK-004)

لفتح Task Manager اضغط `Ctrl + Shift + Esc`

| الأمر | ماذا تقرأ |
|---|---|
| `Win + R` ثم `winver` | إصدار Windows 11 ورقم البناء |
| `Win + R` ثم `msinfo32` | `System Model` (مكتبي أو لابتوب) و`Processor` و`Installed Physical Memory` |
| `Task Manager > Performance` | كل قرص (النوع والحجم)، واسم الـ GPU، و`Dedicated GPU memory` |
| `cmd.exe` ثم `nvidia-smi` | اسم البطاقة ورقم الدرايفر (انسخ النص كاملا) |

اكتب الإجابات الآن في ملف نصي مؤقت، وانقلها إلى `05_Docs\PROJECT_NOTES.txt` بعد إنشاء الهيكل في القسم 6.2، واكتب معها كيف توصل الشاشة الآن (DP أو HDMI أو USB-C)

إذا كان جهازك لابتوب بكرتين (كرت مدمج مع NVIDIA): افتح `Settings > System > Display > Graphics` وأضف Resolve بوضع High performance ⚠ (فحص CHK-004، والإعداد غير موثق في الدليل)

واترك `Hardware-accelerated GPU scheduling` على افتراضيه، ولا تغيره إلا لتشخيص مشكلة ⚠ (فحص CHK-004)

### 3.2 متطلبات Blackmagic المعلنة لـ 21.1.1

| البند | القيمة المعلنة | علامة |
|---|---|---|
| نظام التشغيل | Windows 10 Creators Update أو أحدث (جهازك Windows 11) | ✔ |
| الذاكرة RAM | 16 GB، و32 GB عند استعمال Fusion | ✔ |
| كرت الشاشة | VRAM لا تقل عن 4 GB، ويدعم OpenCL 1.2 أو CUDA 12.8 | ✔ |
| درايفر NVIDIA | Studio Driver بالرقم 581.57 أو أحدث | ✔ |
| أدوات AI المتقدمة | VRAM لا تقل عن 16 GB | ✔ |
| الريندر في الخلفية (Background rendering) | RAM لا تقل عن 32 GB وVRAM لا تقل عن 12 GB | ✔ |

بطاقتك من جيل Ada (RTX 40): فيها NVENC للترميز ◐، وليس فيها فك 4:2:2 بالعتاد ◐ (جداول Puget، وفحص CHK-044 يؤكد ما يخص H.265)

إذا كانت VRAM عندك أقل من 16 GB فقد تظهر تحذيرات في أدوات AI الثقيلة: اختبر ولا تفترض أنها لن تعمل ⚠ (فحص CHK-085)

### 3.3 قاعدة الدرايفر

> **قاعدة:** استعمل NVIDIA **Studio** Driver (وليس Game Ready) بالرقم 581.57 أو أحدث، ثبت نسخة تعمل عندك طوال المشروع، ولا تحدث الدرايفر في منتصفه

- الفرع Studio والحد الأدنى 581.57 ✔ من Readme، والحد الأدنى يرتفع مع الإصدارات الرئيسية، فاقرأ Readme كل إصدار قبل أن تحدث Resolve
- تثبيت نسخة الدرايفر طوال المشروع ◐ ممارسة
- شغل أحدث 21.1.x ✔: Readme الإصدار 21.0.2 يقول "Addressed H.264 and H.265 NVIDIA decode performance"، وReadme الإصدار 21.1.1 يقول "Improved NVIDIA decode memory usage for some R3D NE clips"، ولا تعتمد على تقارير فردية عن بناء بعينه
- إذا انهار Resolve بعد تحديث الدرايفر، ثبت إصدار درايفر Studio السابق الذي كان يعمل عندك ◐ ممارسة
- لمعرفة هل الدرايفر Studio: افتح NVIDIA app أو `NVIDIA Control Panel > Help > System Information` ⚠ (فحص CHK-008)
- لتحويل درايفر Game Ready إلى Studio: 1) افتح صفحة Drivers في موقع NVIDIA، 2) اختر نوع الدرايفر Studio وبطاقتك RTX 40 (أو استعمل NVIDIA app)، 3) ثبته وأعد تشغيل Windows، 4) اكتب الرقم من `nvidia-smi` ⚠ (فحص CHK-008، فواجهة الموقع غير موثقة هنا)

> 📷 **[SHOT-02-02 | P1]** لقطة واحدة تجمع نافذتين متجاورتين: نافذة `cmd.exe` بعد الأمر `nvidia-smi` وظاهر فيها اسم البطاقة ورقم الدرايفر وذاكرة البطاقة، ونافذة NVIDIA app أو `NVIDIA Control Panel > Help > System Information` وظاهر فيها نوع الدرايفر (Studio أو Game Ready) ورقمه

> 📷 **[SHOT-02-03 | P1]** `Task Manager > Performance > GPU`، وظاهر اسم البطاقة و`Dedicated GPU memory`

> **تحقق على جهازك (CHK-004 وCHK-008):** المتوقع: اسم RTX 40 (Ada) ودرايفر 581.57 أو أحدث من الفرع Studio، وإذا كان الدرايفر Game Ready فثبت Studio من موقع NVIDIA واكتب رقمه
>
> أرسل نص `nvidia-smi` كاملا ولقطتي SHOT-02-02 (تضم نوع الدرايفر) وSHOT-02-03

## 4. إعدادات Windows وNVIDIA: الصورة تصل للشاشة كما هي

حسب Microsoft Learn، حين يكون Advanced Color غير مفعل لا يجري Windows أي إدارة ألوان على مخرجات التطبيق ✔

والاستنتاج منه ◐: قيم عارض Resolve تصل إلى الشاشة بلا تحويل ثان، وإعداد الشاشة نفسها هو الذي يحدد الصورة

لذلك مهمتك في Windows أن تطفئ كل ما قد يضيف تحويلا (فحص CHK-009، 10 دقائق)

اضغط `Win + I` واختر `System > Display` ثم اختر الشاشة P32p-20 من أعلى الصفحة قبل أي تغيير، ولفتح NVIDIA Control Panel اكتب اسمه في قائمة Start

| الطبقة | الإعداد (الاسم كما يظهر) | القيمة | علامة |
|---|---|---|---|
| Windows | `Settings > System > Display > HDR` (مفتاح `Use HDR`) | OFF | ◐ (فحص CHK-009) |
| Windows | `Auto HDR` | OFF | ◐ (فحص CHK-009) |
| Windows | `Night light` | OFF | ◐ (فحص CHK-009) |
| Windows | `Automatically manage color for apps` (الاسم من وثيقة طرف ثالث، ويظهر على Windows 11 22H2 فما فوق لشاشات SDR مؤهلة فقط) | OFF إن وجد | ⚠ (فحص CHK-009) |
| Windows | ملف ICC للشاشة: قائمة Start > اكتب `Color Management` > تبويب `Devices` | لا ملف مرتبط بالشاشة أثناء التلوين، وإذا وجدت ملفا مرتبطا فأزله من القائمة لهذا الجهاز واكتب اسمه | ◐ (فحص CHK-009) |
| Windows | أدوات من نوع f.lux وبرامج حماية العين | مغلقة | ◐ |
| NVIDIA | الدرايفر | Studio 581.57 أو أحدث | ✔ |
| NVIDIA | `Change resolution` و`Use NVIDIA color settings` | انظر الفصل 3 (القسم 3.3، فحص CHK-010) | ⚠ (فحص CHK-010) |
| NVIDIA | `Adjust desktop color settings` | الافتراضي: Brightness 50، Contrast 50، Gamma 1.00، Digital vibrance 50، Hue 0 | ⚠ (فحص CHK-010) |
| Resolve | `Project Settings > Master Settings > Video Monitoring` | لا تلمسه (هذا القسم يتحكم بإشارة بطاقة فيديو I/O وأنت بلا بطاقة) | ✔ |

- ملف ICC: أداة المعايرة تكتب منحنى داخل الـ GPU يؤثر على كل التطبيقات، فلا تربط ملفا بالشاشة أثناء التلوين ◐
- مفتاح HDR: الدليل يقول إن عارضات HDR في Resolve على Windows تتبع هذا المفتاح، وإطفاؤه لـ SDR احتياط مستنتج وليس نصا في الدليل ◐
- وثائق Lenovo لا تذكر HDR، فلا تعامل الشاشة كشاشة HDR ✔
- الكابل (DisplayPort بين البطاقة والشاشة) وقائمة الشاشة OSD ومعنى 10 bpc وفحص التشرط (Banding): انظر الفصل 3 (فحوصات CHK-010 وCHK-011 وCHK-051)
- مقياس العرض: جرب 100 و125 و150% في `Settings > System > Display > Scale` (أعد تشغيل Resolve بعد كل تغيير) واختر ما يبقي العقد والمقاييس واللوحات مقروءة، وعند 100% يعرض العارض البكسل 1:1 في الغالب ⚠ (فحص CHK-026)
- التخطيط العمودي: `Preferences > User > UI Settings > Use optimized UI layouts for vertical video` يبقى ON، وهو الافتراضي (الدليل الرسمي ص 110) ✔

> 📷 **[SHOT-02-04 | P1]** لقطة واحدة تجمع نافذتين متجاورتين: `Settings > System > Display` للشاشة P32p-20، وبجانبها صفحة HDR وفيها مفتاحا `Use HDR` و`Auto HDR` في حالة OFF، و`Night light` OFF

> 📷 **[SHOT-02-05 | P2]** نافذة Windows `Color Management` تبويب Devices والشاشة P32p-20 مختارة، وظاهر هل يوجد ملف ICC مرتبط بها

> 📷 **[SHOT-02-06 | P1]** لوحة `NVIDIA Control Panel > Display > Change resolution` مع الخيار `Use NVIDIA color settings` مفعلا، وظاهر فيها الدقة 3840 x 2160 و60 Hz و`Output color format` و`Output color depth` و`Output dynamic range`

> **تحقق على جهازك (CHK-009 وCHK-010):** المتوقع: كل شيء OFF، وإذا لم تجد مفتاحا فاكتب أنه غير موجود ولا تبحث عنه أكثر
>
> أرسل لقطات SHOT-02-04 وSHOT-02-05 وSHOT-02-06، وإذا اختلف اسم الخيار قليلا عندك، ابحث عن نفس الوظيفة
>
> اكتب القيم الفعلية لـ `Output color format` و`Output color depth` و`Output dynamic range` حتى لو اختلفت عن الجدول (تفاصيل الكابل والفحص: انظر الفصل 3)

## 5. Resolve Preferences

## 7. فك الترميز على RTX 40

### 7.1 ماذا يفعل العتاد لكل صيغة

أربعة مصطلحات قبل الجدول:

- Debayer: تحويل بيانات RAW الخام إلى صورة ملونة
- Chroma 4:2:0 و4:2:2: كمية معلومات اللون المحفوظة في الملف، و4:2:2 أثقل من 4:2:0
- الفك بالعتاد (Hardware decode): شريحة مخصصة في البطاقة (NVDEC) تفك الفيديو بدل الـ CPU، ويقابلها NVENC للترميز
- Long GOP: ملف تعتمد إطاراته على إطارات سابقة ولاحقة، فيصعب القفز فيه

لتعرف ترميز مقطعك وعمق لونه وChroma افتح MediaInfo (تثبيته في فحص CHK-002)

| الصيغة | RTX 40 | علامة |
|---|---|---|
| R3D NE 12-bit (`.R3D`) | مسار GPU للـ debayer عبر `Use GPU for R3D`، وقائمة الصيغ المدعومة (codecs21 ص 9) تكتب لـ `.r3d` عبارة "Yes, GPU accelerated"، والأسرع بين الخيارات الثلاثة يحدده فحصك | ✔ / ⚠ (فحص CHK-043) |
| H.265 10-bit 4:2:0 (N-Log، UHD أو 5.4K) | مرشح للفك بالعتاد على أي RTX 40، لأن H.265 في الـ ZR هو 4:2:0 | ◐ (فحص CHK-044) |
| H.264 8-bit 4:2:0 (ملف MP4 المرافق في الكاميرا) | تفكه البطاقة بالعتاد | ◐ (فحص CHK-044) |
| ProRes 422 HQ 10-bit (4:2:2) | يفكه الـ CPU | ◐ (فحص CHK-044) |
| H.264 10-bit وأي H.26x بصيغة 4:2:2 | لا تفكه RTX 40 بالعتاد بحسب جداول Puget ◐؛ وReadme الإصدار 20.0 يذكر `GPU accelerated H.265 4:2:2 decodes on supported Nvidia systems` ✔ بلا تسمية الجيل (وتربطه الصحافة بـ RTX 50 ◐)، ولا يفيد ملفات ZR لأن H.265 فيها 4:2:0 | ◐ (فحص CHK-044) |
| N-RAW (`.NEV`) وProRes RAW HQ | فك الاثنين مدرج في قائمة Blackmagic على Windows بلا علامة Studio، ولا يوجد لهما خيار في لوحة Decode Options، ولا نستعملهما في التسليم قبل اختبارهما (انظر الفصل 6) | ✔ |

- على Windows تضيف Studio تسريع GPU وملفات H.264/H.265 إضافية (قائمة Blackmagic، codecs21 ص 9: "More profiles and GPU acceleration in Studio") ✔، وهذا ما عندك
- هل يفك المقطع بالعتاد فعلا يعتمد على الترميز وعمق اللون وأخذ عينات اللون (Chroma) وقدرات البطاقة، ولا يوجد مؤشر مباشر في Resolve على أنه يستعمل الفك بالعتاد (المصدر Puget) ◐ (فحص CHK-044)
- ترميز NVENC على RTX 40 ◐: H.264 بصيغة 4:2:0 نعم، وبصيغة 4:2:2 لا، وHEVC 10-bit نعم، وAV1 نعم (لا ترفع AV1 إلى إنستغرام)؛ وترميز ProRes على Windows يعمل بالـ CPU ومتاح في النسختين (فحص CHK-091 للإتاحة، وفحص CHK-092 للمرمز NVIDIA مقابل البرمجي، وانظر الفصل 12)
- نصيحة: ملفات N-Log H.265 ذات الـ long GOP إذا تلكأ التقدم فيها (Scrubbing)، حولها إلى DNxHR أو ProRes ◐ ممارسة (فحص CHK-044)

### 7.2 اختبر العتاد بدل أن تصدق الجدول

1. شغل مقطع N-Log H.265 (UHD أو 5.4K) على تايم لاين
2. في `Task Manager > Performance > GPU` اضغط عنوان أحد رسوم المحركات واختر `Video Decode`
3. والخيار `Decode H.264/HEVC using hardware acceleration` مفعل، اكتب حمل `Video Decode` وحمل الـ CPU

5. اختياري (طريقة Puget): نفذ ريندر لتايم لاين من مقطع واحد إلى DNxHR LB والخيار مفعل ثم معطل، وResolve.exe مثبت على نواة CPU واحدة (`Task Manager > Details` > كليك يمين > `Set affinity`)، والزمن الأقصر بوضوح يعني أن الفك بالعتاد يعمل

### 7.3 `Use GPU for R3D`

1. أنشئ تايم لاين فيه مقطع واحد 6K 25p بصيغة R3D NE
2. راقب مؤشر الـ GPU وعداد fps في شريط عنوان العارض (الدليل الرسمي ص 194) مع `Task Manager > Performance > GPU`
3. لكل خيار من `None` و`Debayer` و`Decompression and Debayer` (`Preferences > System > Decode Options`، ثم Save وأعد تشغيل Resolve) شغل 20 ثانية بـ `Decode Quality` Full ثم Half، إن كانت لوحة Camera Raw متاحة عندك ⚠ (فحص CHK-030)
4. إذا كانت اللوحة معطلة تحت إدارة الألوان في Resolve (Resolve Color Management واختصارها RCM، وهي المسار أ الافتراضي، انظر الفصل 7)، فاختبر كل خيار من `None` و`Debayer` و`Decompression and Debayer` بالفك الذي تفرضه RCM على التايم لاين الحالي بلا تبديل Full وHalf، وسجل fps والإطارات الساقطة؛ ولا تعتمد `Timeline Proxy Resolution` بديلا عن `Decode Quality` لأن الدليل يقول إنه لا يفيد حين يستهلك debayer الـ RAW طاقة التشغيل ✔ (الدليل الرسمي ص 196)؛ والبديل الفعلي لحمل RAW تحت المسار أ هو Proxy Media أو Optimized Media (الخطوة 5 من السلم)
5. اكتب fps والإطارات الساقطة وحمل الـ GPU في جدول من 6 نتائج (3 خيارات في حالتين)
6. احتفظ بالخيار الذي بلا مؤشر أحمر وبلا إطارات ساقطة
7. إذا ظهرت إطارات مشوشة جرب `GPU processing mode` = CUDA صراحة (`Preferences > System > Memory and GPU`)

### 8.6 تنظيف ذاكرة الريندر المؤقتة

- ذاكرة الريندر المؤقتة دائمة وتبقى بعد إغلاق المشروع ✔ (ص 206)، وتكبر بسرعة مع 6K RAW ◐ (تقدير: راقب حجم مجلد `CacheClip` بعد أول جلسة تلوين واكتبه في `PROJECT_NOTES.txt`)
- `Playback > Delete Render Cache` بخياراته `All` و`Unused` و`Selected Clips` يعمل على المشروع المفتوح (ص 206) ✔
- `Playback > Manage Render Cache` (Cache Manager) يعرض ذاكرة الريندر المؤقتة لمشاريع كل المكتبات دون فتحها، والزر `Clear Selected Cache` يحذف بلا تحذير وبلا تراجع (ص 206) ✔، فراجع اختيارك مرتين
- الحذف التلقائي: `Preferences > User > Cache Management` (ص 207)
- احذف الـ Optimized Media يدويا من Windows (ص 200)
- نظف بعد التسليم وبين المشاريع، ولا تحذف ذاكرة مشروع تعمل عليه الآن وتحتاجها
- `Render cache format`: اترك الافتراضي إلا إذا ظهر تشرط (Banding) في التشغيل المخزن، والصيغ المنتهية بـ HDR وصيغة 16-bit float وProRes 4444 وDNxHR 444 تحفظ البيانات الخارجة عن النطاق، والصيغ العادية تقصها (ص 198 و203) ✔

> **خطأ شائع:** وضع مجلد الـ cache والـ Proxy على قرص النظام لأنك لم تحدد قرص cache، أو ترك Proxy مفعلا عند التسليم دون قراءة الخانات في القسم 8.5

> **تحقق على جهازك (CHK-031 وCHK-045):** اكتب أسماء قوائم Playback كما تظهر والقيم الافتراضية للوحة Optimized Media and Render Cache، ثم جرب السلم على مقطع R3D NE بهذا الترتيب:
>
> 1. استورد مقطع R3D NE ومعه ملف MP4 المرافق، وأضف عمود `Proxy` في عرض List لـ Media Pool، واكتب ما يظهر فيه (None أو Offline أو الدقة)، وإن لم يرتبط جرب `Link Proxy Media`
> 2. في `Project Settings > Master Settings > Optimized Media and Render Cache` اضبط `Proxy media resolution` = Half و`Proxy media format` = DNxHR HQ، ثم كليك يمين على المقطع > `Generate Proxy Media`، ثم `Prefer Proxies` ثم `Prefer Camera Originals` وسجل fps في كل حالة
> 3. كليك يمين على المقطع > `Generate Optimized Media`، وبدل `Playback > Use Optimized Media if Available` وسجل fps
> 4. اضبط `Render Cache` = `Smart` وأضف عقدة Noise Reduction ثقيلة، وراقب الأشرطة الحمراء والزرقاء وسجل fps
> 5. غير إعداد Camera Raw للمقطع المحسن وشاهد حذف وسائطه المحسنة (قد تكون اللوحة معطلة تحت RCM ⚠ فحص CHK-030)
> 6. تأكد أن Deliver يريندر من الأصول افتراضيا
>
> اكتب fps في جدول من 5 أسطر (أصل، Proxy، Optimized، Smart Cache، بعد تغيير Camera Raw)، وأرسل لقطات SHOT-02-18 وSHOT-02-19 وSHOT-02-20 مع الجدول نصا
